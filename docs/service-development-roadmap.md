## 1. 서비스 정의 — 무엇을, 왜 만드는가

두 선행 문서에서 확인한 결론을 그대로 잇는다.

- **문제**: 전세사기는 계약 전 정보 비대칭, 특별법 사각지대, 계약 후 2차 피해라는 세 층위로 구성되어 있다([jeonse-fraud-deep-research.md](jeonse-fraud-deep-research.md) 7장).
- **기존 서비스의 공백**: 세이프홈즈·집토스·내집스캔 등 최소 8개 서비스가 이미 "계약 전 위험도 진단"을 제공하고, 2026년부터는 정부 임대차 통합정보시스템이 이 기능을 공공재화한다. 반면 **①계약 후 지속 모니터링, ②특별법 사각지대 자가진단, ③2차 피해 대응 가이드**는 뚜렷한 서비스가 확인되지 않았다([jeonse-fraud-existing-services-report.pdf](jeonse-fraud-existing-services-report.pdf) 6장).

**따라서 이 서비스는 "위험도 점수 하나 보여주고 끝"이 아니라, 계약 전~계약 중~피해 발생 이후까지 세입자의 전체 여정(journey)을 따라가며 공백을 메우는 것을 목표로 한다.** 이는 동시에 4주 내 단계적으로 쌓아 올리기에도 적합한 구조다 — 계약 전 진단이 없으면 사각지대 진단도, 모니터링도 의미가 없기 때문에 자연스러운 개발 순서가 된다.

## 2. Phase 구성 원칙

Claude의 Phase 추천은 다음 3가지 기준으로 순서를 정했다.

1. **의존성**: 뒤 단계 기능이 앞 단계 데이터/화면을 재사용할 수 있는 순서로 배치 (예: Phase 3의 모니터링은 Phase 1의 계약 입력 데이터를 그대로 사용).
2. **차별화 우선순위**: 이미 레드오션인 기능(계약 전 진단)은 최소 기능만 빠르게 구현하고, 시장 공백(사각지대 진단, 모니터링, 2차 피해 가이드)에 더 많은 개발 시간을 배분.
3. **검증 가능성**: 매주 "실제로 눌러볼 수 있는" 결과물이 나오도록 설계 — 4주 뒤에야 뭔가 보이는 구조를 피함.

| Phase | 주차 | 한 줄 목표 | 시장 포지션 |
|---|---|---|---|
| 1 | 1주차 | 계약 전 위험 신호를 입력만으로 확인 | 진입장벽(필수 기능, 차별화 아님) |
| 2 | 2주차 | "나는 특별법 보호를 받을 수 있는가"를 미리 안다 | **시장 공백 ①** |
| 3 | 3주차 | 계약 이후에도 위험 변화를 계속 알려준다 | **시장 공백 ②** |
| 4 | 4주차 | 이미 피해를 입었을 때 다음 행동을 안내한다 | **시장 공백 ③** |

## 3. Phase 1 (1주차) — 계약 전 위험 자가진단 MVP

### 목표
사용자가 주소·보증금·전세가 등 최소 정보만 입력하면 기본적인 위험 신호를 즉시 확인할 수 있는 핵심 골격을 완성한다.

### Claude 추천 근거
경쟁 서비스가 이미 많은 영역이지만, **이 기능 없이는 Phase 2~4가 성립하지 않는 전제 조건**이다. 따라서 정교함보다 "입력 → 결과" 흐름을 빠르게 완성하는 데 집중하고, 공공데이터(전세가율 등)를 활용해 최소한의 신뢰도를 확보한다.

### 핵심 기능
- 주소 검색 (도로명주소 API 연동)
- 보증금·매매시세(또는 KB 시세 참고치) 입력 → **전세가율 자동 계산** 및 위험 구간(안전/주의/위험) 표시
- 국토교통부 실거래가 공개 API 연동으로 인근 시세 비교
- 등기부등본 열람 안내 및 체크포인트 가이드(직접 발급 대체는 하지 않되, "무엇을 봐야 하는지" 안내)
- 결과 리포트를 저장/공유할 수 있는 링크 생성

### 기술 요소
- Next.js App Router 페이지: `/diagnose` (입력 폼), `/report/[id]` (결과)
- 국토교통부 실거래가 Open API, 도로명주소 API 연동
- 데이터 저장: 우선 서버리스 DB(Supabase 또는 Vercel Postgres)로 최소 스키마 구성

### 완료 기준 (DoD)
- [ ] 주소 입력 → 전세가율 계산 → 위험 등급 표시까지 엔드투엔드 동작
- [ ] 결과 리포트 URL 공유 가능
- [ ] 실거래가 API 응답 실패 시 안내 문구로 graceful fallback

## 4. Phase 2 (2주차) — 특별법 사각지대 자가진단

### 목표
「전세사기피해자 지원 및 주거안정에 관한 특별법」의 피해자 인정 4대 요건을 사용자가 스스로 체크해보고, "지금 계약이 향후 특별법 보호 대상이 될 수 있는지"를 사전에 가늠하게 한다.

### Claude 추천 근거
[jeonse-fraud-deep-research.md](jeonse-fraud-deep-research.md) 7.2절과 [jeonse-fraud-existing-services-report.pdf](jeonse-fraud-existing-services-report.pdf) 6.4절에서 공통으로 확인된 **명확한 시장 공백**이다. 특별법 부결·기각 비율이 높다는 사실이 이미 리서치로 검증되어 있어, 사용자 공감을 얻기 쉽고 기술적으로도 "체크리스트 + 조건 분기" 수준이라 4주차 안에 구현 난이도가 낮다. Phase 1에서 입력받은 보증금·계약 정보를 그대로 재사용할 수 있어 개발 효율이 높다.

### 핵심 기능
- 4대 요건 기반 인터랙티브 체크리스트
  1. 대항력·확정일자 구비 여부
  2. 임차보증금 한도(원칙 5억 원 이하) 충족 여부
  3. 동일 임대인의 다수 피해 발생 가능성(같은 건물/임대인 피해 사례 검색 연계)
  4. 임대인의 기망 의도를 의심할 정황 여부
- 요건별 "지금 무엇을 준비해야 하는지" 안내 (예: 확정일자 미비 시 즉시 조치 안내)
- 결과에 따라 관할 지자체 상담센터(서울시·경기도 등, Phase 4에서 확장) 연결 안내

### 기술 요소
- Phase 1의 리포트 데이터 모델 확장 (특별법 진단 결과 필드 추가)
- 체크리스트 로직은 클라이언트 상태 관리로 충분 (별도 백엔드 로직 최소화)

### 완료 기준 (DoD)
- [ ] 4대 요건 체크리스트가 Phase 1 리포트 페이지에 통합되어 표시
- [ ] 각 요건 미충족 시 구체적 행동 안내 문구 노출
- [ ] 체크리스트 결과가 Phase 1 리포트 URL에 함께 저장·공유됨

## 5. Phase 3 (3주차) — 계약 후 지속 모니터링

### 목표
계약 시점 1회성 진단에서 벗어나, 임차 기간 동안 등기 변동 등 위험 신호가 발생하면 사용자에게 알려주는 최소 기능을 구현한다.

### Claude 추천 근거
[jeonse-fraud-existing-services-report.pdf](jeonse-fraud-existing-services-report.pdf) 6.2절에서 확인했듯 "계약 후 사후 변수 대응"은 집지켜 정도만 근접해 있을 뿐 뚜렷한 표준 서비스가 없는 **가장 강력한 차별화 지점**이다. 다만 실시간 등기부 변동 API 연동은 비용·기술 난이도가 높으므로, 4주차 프로젝트 범위에서는 **"정기 리마인더 + 수동 재확인 유도"** 형태의 경량 MVP로 구현하고, 실제 자동 모니터링은 Post-MVP(9장)로 넘긴다.

### 핵심 기능
- 계약 정보 기반 주요 일정 알림(이메일/브라우저 알림): 전입신고·확정일자 완료 여부 재확인, 등기부등본 재열람 권장 주기(예: 분기 1회) 리마인더
- "지금 다시 확인하기" 버튼 → Phase 1 진단 로직 재실행 후 이전 결과와 비교해 변동 여부 표시(전세가율 변화 등 공개 데이터 기반 비교는 자동화 가능)
- 위험 신호 감지 시(예: 인근 시세 급락) 알림 발송

### 기술 요소
- 알림 발송: Resend/이메일 API 또는 Web Push
- 정기 실행: Vercel Cron 또는 유사 스케줄러로 주기적 재계산 배치
- Phase 1 데이터 모델에 "리포트 이력(history)" 테이블 추가하여 시점별 비교 가능하도록 확장

### 완료 기준 (DoD)
- [ ] 사용자가 알림 수신 채널(이메일 등) 등록 가능
- [ ] 최소 1종 이상의 자동 재확인 알림(예: 시세 변동 기반)이 실제 발송됨
- [ ] 리포트 이력 화면에서 이전 진단과 최신 진단 비교 가능

## 6. Phase 4 (4주차) — 2차 피해 대응 가이드 & 완성도

### 목표
이미 피해가 발생했거나 발생 위험이 높은 사용자에게 구체적인 다음 행동(법률구조공단 연계, 은행 유예제도 안내, 지자체 상담센터 연결)을 안내하고, 전체 서비스의 완성도를 높인다.

### Claude 추천 근거
[jeonse-fraud-deep-research.md](jeonse-fraud-deep-research.md) 7.3절에서 확인한 **채무불이행 전환, 연대보증인 추심 등 2차 피해**는 기존 어떤 서비스도 다루지 않는 완전한 공백이다. 다만 이 영역은 법률·금융 정보의 정확성이 중요해 자체 판단 로직보다는 **"올바른 기관으로 안내하는 허브" 역할**에 집중하는 것이 4주차 범위에서 현실적이다. 동시에 마지막 주차이므로 전체 사용자 여정(Phase 1→4)을 하나의 흐름으로 통합하고 QA·반응형 대응 등 완성도 작업을 함께 진행한다.

### 핵심 기능
- 상황별 대응 가이드 페이지: "보증금을 못 받았어요", "이미 경매가 진행 중이에요", "채무불이행자로 등록됐어요" 등 시나리오별 체크리스트와 연계 기관 안내(대한법률구조공단, HUG, 지자체 주거복지센터, 은행 유예제도 신청 창구)
- Phase 2 사각지대 진단 결과와 연동해 "당신은 어느 시나리오에 해당하는지" 자동 안내
- 전체 서비스 온보딩 플로우 정리, 반응형 UI 점검, 에러/엣지케이스 QA

### 기술 요소
- 정적 콘텐츠 기반 가이드 페이지(별도 백엔드 로직 불필요, 유지보수 용이성 우선)
- Phase 1~3 전체 플로우 통합 테스트

### 완료 기준 (DoD)
- [ ] 최소 3개 이상 시나리오별 대응 가이드 페이지 완성
- [ ] Phase 1→2→3→4가 하나의 사용자 흐름으로 자연스럽게 연결
- [ ] 모바일/데스크톱 반응형 QA 완료

## 7. 기술 스택 및 아키텍처 개요

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js 15 (App Router) + React 19 + TypeScript | 현재 저장소 기존 스택 그대로 활용 |

| 알림 | Resend(이메일) 또는 Web Push | Phase 3에서 사용 |
| 배포 | Vercel | Next.js와 궁합, Cron Job 기본 지원 |

## 8. Phase별 완료 기준(DoD) 요약표

| Phase | 핵심 산출물 | 주요 리스크 |
|---|---|---|

## 9. Post-MVP — 4주 이후 확장 방향
